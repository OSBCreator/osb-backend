RSEI Model™ API

Model · v2.0 Reference · OSB/TECH/RSEI/001/2026 API · v1

The RSEI Model classifies social engineering and romance fraud across four behavioural pillars. This API returns a structured assessment from eight scored inputs. It is intended for dating and social platforms, financial institutions and researchers.

01Base URL

https://ufnityyhmfzahxkjmlgo.supabase.co/functions/v1/osb-api

02Authentication

All endpoints except the specification require an API key issued by OSB, sent as a header:

x-api-key: osb_xxxxxxxxxxxxxxxxxxxxxxxx

Keys are issued per organisation, rate-limited per hour, and revocable. To request one, contact OSB.

03Get the specification

GET /v1/spec

Public and unauthenticated. Returns the complete model definition — pillars, questions, scale and classification bands — so you can build against it and detect changes.

curl https://ufnityyhmfzahxkjmlgo.supabase.co/functions/v1/osb-api/v1/spec

04Request an assessment

POST /v1/assess

All eight answers are required, each an integer 1–5, where 1 is benign and 5 is the strongest indicator.

curl -X POST \
  .../functions/v1/osb-api/v1/assess \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_KEY" \
  -d '{
    "answers": {
      "r1": 5, "r2": 4,
      "s1": 4, "s2": 3,
      "e1": 5, "e2": 5,
      "i1": 5, "i2": 4
    }
  }'

Response

{
  "ok": true,
  "version": "v2.0",
  "reference": "OSB/TECH/RSEI/001/2026",
  "score": 18,
  "score_max": 20,
  "pillars": { "R": 5, "S": 4, "E": 5, "I": 5 },
  "tier": "Critical — Exploitation in Progress",
  "risk": "critical",
  "e_pillar_trigger": true,
  "dominant_pillar": "R",
  "assessed_at": "2026-09-04T12:00:00.000Z"
}

05The four pillars

IDPillarWhat it measures
RRelationship AccelerationIntimacy and commitment established on a compressed timeline
SScript ConsistencyA rehearsed persona that holds under scrutiny because it is material, not memory
EEmotional ManipulationAffection, guilt or urgency used to override judgement at decision points
IIncremental ExtractionRequests escalating in deniable stages, each framed as the last

Each pillar scores 1–5 as the rounded mean of its two questions. Core score = R + S + E + I, range 4–20.

06Classification bands

ScoreTier
4–11Low Behavioural Risk
12–16High Probability Romance Scam
17–20Critical — Exploitation in Progress

07The E-pillar trigger

e_pillar_trigger returns true when E ≥ 4, independent of the total score. It indicates victim support is warranted regardless of whether any financial loss occurred.

It exists because emotional harm and financial harm do not correlate reliably. Treating a low-loss case as a low-harm case is the most common failure in this field.

08Errors

StatusMeaning
400Missing or invalid answers. The response names the specific fields.
401Missing, invalid or revoked API key.
429Rate limit exceeded for your key.

The API never returns a partial or defaulted score. If input is incomplete it returns an error rather than a number that looks valid but is not.

09What OSB stores

Each call logs the API key, endpoint, resulting score and tier — used for volume attribution and rate limiting. Answer content is not stored. OSB receives no information identifying the individual being assessed.

10Conditions of use

  • What the score measures. RSEI classifies behavioural pattern — the structure of an interaction, not the identity of a participant. This is the source of its power: behaviour is observable and consistent across operators, while identity signals are trivially forged. It follows that an assessment describes a pattern, not a person, and integrators should surface it as such.
  • Ordinal classification, not probability. The Core Rating is an ordinal score across defined bands. Probability calibration — the distribution of scores across confirmed outcomes — is under active development through OSB's case cohort and will be published as versioned reference ranges. Until then, present the band, not a percentage.
  • Versioning. Breaking changes are published under a new version path; /v1 remains stable. Every response carries the model version and specification reference, so any result is traceable to the exact revision that produced it.
